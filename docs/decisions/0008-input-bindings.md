# 0008 — Input bindings as data, the player's own in a file apart

- Context: seven `*_input_map.gd` hard-coded the bindings of their scene and registered them when the scene first opened. Nothing could list, show or change them, and the hints were static strings for both device families.
- Decision: one table, `data/input.json`: per scene and action the default keyboard and mouse events, the controller events and the deadzone, written in a short notation (`key:W`, `mouse:left`, `pad:a`, `axis:left_y-`, `axis:rt`; `InputNotation`). `InputTable` in `src/render/input/` registers every action once at boot (from `App`) under the names the scenes already use — `<scene>_kb_<action>`, `<scene>_pad<n>_<action>` per joypad id, `castle_<action>` for all devices. The `*_input_map.gd` keep their helpers only. A test holds the registered actions, events and deadzones against a golden list captured from the old tables (`src/render/input/input_golden.txt`).
- Decision: the player's bindings are what differs from the defaults, kept in `user://input.cfg` (`InputOverrides`: one section per scene, entries `keys/<action>` and `pad/<action>` with a list of events) and put over the defaults at boot. They are not part of `settings.cfg`: options have fixed keys and ranges, bindings follow the table. An entry that no longer fits the table is ignored, so the file needs no version.
- Decision: a rebind applies to one scene and one device family — the keyboard and mouse set, or the controller set of both joypads alike. Inside a scene and family an event belongs to one action: the action that had it keeps its other events or takes over the old ones (`InputRebind`). Mouse input the scenes read without an action (`fixed` in the table), locked actions (`menu`, `close`) and the events of the pause menu (Esc, Start) cannot be bound; `ui_accept`, `ui_cancel` and `app_pause` stay in `App`.
- Decision: prompts take their words from the bindings in use: `InputGlyphs` names keys by the label of the player's keyboard layout and controller buttons the Xbox way, `InputPrompt` shows the binding of the device family used last.
- Consequences: a new action is a line in `data/input.json`, a line in the golden list and a text key `INPUT_<SCENE>_<ACTION>`; no code registers bindings any more. PlayStation and Switch glyph sets and bindings per controller are not covered. `input.cfg` belongs to the files Steam Auto-Cloud syncs, next to `settings.cfg`.
